01

One viewer, one 64-bit block

The platform hides who is watching. User 42 and session 0 go into one 64-bit block. A 32-byte master key comes from the operating system’s random generator, and HKDF derives three keys for this film from it.

02

31 rounds, still 64 bits

PRESENT-128 scrambles the block in 31 rounds: a round key, an S-box on every 4 bits, then the bits change places. Nothing grows. A 32-bit SipHash tag lets the platform reject a wrong or forged mark, and BCH adds 92 parity bits against damage.

The exact formula

C = PRESENT-128(enc_key, block)
tag = SipHash-2-4(mac_key, alg ‖ film_id ‖ SHA-256(enc_key)[:8] ‖ C)[:32 bits]
codeword = BCH(188, 96) of C ‖ tag

03

Each bit gets its own blocks

The frame is cut into 8×8 pixel blocks. Bit 0 goes to block 0, bit 1 to block 1, in reading order. After block 187 the codeword starts again, so every bit lands in about 56 blocks of each frame.

04

Five numbers move a little

Block (21, 41) sits between the older man’s eyes and carries bit 17, a 1. In the frequency domain only five low coefficients move, each by about 4.645, along a secret ±1 pattern from stego_key. The pixels change by a few grey levels.

The exact formula

c′ = c + α_b × s × u on zigzag coefficients 1 to 5. α_b is stronger in textured blocks and weaker in flat ones (film average 3.098).

06

From a leaked copy to a user

The platform lines the leak up with its original, scores every block against the secret pattern and adds up the evidence for each of the 188 bits. BCH repairs what broke. Only a valid MAC lets the block be decrypted.
